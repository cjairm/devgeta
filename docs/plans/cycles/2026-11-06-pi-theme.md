## 1. Domain Context

`dg theme set <name>` re-renders every installed themed app from one palette
file (`configs/themes/<name>.yaml`, ADR-0043), transactionally. Seven apps take
part today. Pi (ADR-0059, ADR-0060) does not, so it shows Pi's own colors
inside an otherwise uniform setup.

This is step one of two. Step two installs `pi-powerline-footer`, which colors
Pi's footer from the active Pi theme — so Pi must be on a devgeta theme first.
Design: [ADR-0061](../../decisions/ADR-0061-pi-is-a-themed-surface-with-one-devgeta-owned-theme-file.md).

## 3. Objective

`dg configure pi` leaves Pi on a `devgeta` theme rendered from the current
palette, `dg theme set <name>` restyles a running Pi within the same
transaction as the other seven apps, and Pi's documented key handling works
inside devgeta's tmux.

### Steps

#### Step 1: Theme template

Write `devgeta.json.tmpl` with `$schema`, `"name": "devgeta"`,
`"appearance": "dark"`, `vars` from palette roles, and all 51 required
`colors` keys plus the optional scrollbar/search keys. `text` is `""`.
Verify: a test renders it for every shipped theme and checks the result
parses and contains exactly the schema's required keys (key list held in the
test, sourced from the schema URL in a comment).

#### Step 2: Register the surface

`surfaceGroup`, `Manifest()`, `themedApps`, contract comment. Pi's
`ForceConfigure` resolves `theme.CurrentDefinition()` and calls
`ForceConfigureTheme`, like OpenCode.
Verify: `go test ./internal/theme/ ./cmd/`.

#### Step 3: Configure writes the theme and selects it

`ForceConfigureTheme(def)` renders the template to
`~/.pi/agent/themes/devgeta.json` and nothing else. Configure (soft/force)
additionally calls the settings merge, then installs extensions as today.
Settings merge: read → `map[string]json.RawMessage` → set `theme` → marshal
indented → `files.WriteFileAtomic`. Parse failure returns an error naming the
file.
Verify: tests for absent file, existing `theme` kept on soft, replaced on
force, `packages` preserved byte-for-byte as a value, unparseable file errors.

#### Step 4: tmux extended keys

```tmux
set -g extended-keys on
%if "#{>=:#{version},3.5}"
set -g extended-keys-format csi-u
%endif
```

Verify: root-package embedded-config test asserts both lines and the gate.

#### Step 5: Alacritty Option+Enter (macOS)

The Alacritty template has no platform gate today, so this step adds one.
`ForceConfigureTheme` passes `"IsMac": a.Base.IsMac()` in its template data —
the platform check CLAUDE.md §7 names, and mockable through `Base`, so tests
cover both platforms without depending on `runtime.GOOS`. `IsMac` is the same
field name `configs/templates/devgeta.zsh.tmpl` already gates on. The template
wraps the binding:

```toml
{{if .IsMac}}
[[keyboard.bindings]]
key = "Enter"
mods = "Alt"
chars = "\u001b[13;3u"
{{end}}
```

Verify: alacritty tests render with the mock reporting macOS (binding
present) and Linux (binding absent); golden updated.

## 6. Verification Plan

### Automated

The targeted commands in §2.

### Manual (maintainer runs — each writes to the real machine; ask first)

1. `make build`, install the binary.
2. `dg configure pi --force` → `~/.pi/agent/themes/devgeta.json` exists;
   `settings.json` has `"theme": "devgeta"` and its `packages` unchanged.
3. Open `pi`; colors match tmux/Neovim.
4. With Pi open, `dg theme set tokyonight` → Pi restyles without restart.
   `dg theme set default` → back.
5. `dg configure tmux --force`, then a **new tmux server** (`tmux kill-server`
   ends every session — maintainer's call). In Pi inside tmux: Shift+Enter
   inserts a newline, Enter submits, Option+Enter queues a follow-up.
6. Same check in Ghostty and Alacritty, and confirm Option+Enter at a bare zsh
   prompt behaves acceptably (Risk 2).

### Regression

- Claude Code and Neovim inside tmux still handle Shift+Enter and normal keys.
- `dg theme set` on a machine without Pi still skips it ("not installed").

## 7. Risks & Trade-offs

| Risk                                                                                          | Likelihood | Mitigation                                                                                                  |
| --------------------------------------------------------------------------------------------- | ---------- | ----------------------------------------------------------------------------------------------------------- |
| Pi adds a required color role → our theme is rejected at startup                              | Med        | Template test pins the key list; Pi reports invalid themes and falls back. Update the template when Pi does |
| Alacritty binding makes Option+Enter insert junk in non-CSI-u programs                        | Med        | macOS only; separate step; drop it if step 6 of manual verification is bad                                  |
| tmux needs `terminal-features ',xterm*:extkeys'` for the outer terminal to send extended keys | Med        | Manual step 5 decides; add it only if keys fail                                                             |
| `extended-keys on` changes key behavior in other TUIs inside tmux                             | Low        | Regression check with Claude Code and Neovim                                                                |
| Writing Pi's settings while Pi is running races with Pi's own writes                          | Low        | Atomic rename; only written by configure, never by `dg theme set`                                           |

### Trade-offs Made

- Fixed theme name over one file per devgeta theme — see ADR-0061 §2.
- `dg theme set` respects a user's own Pi theme choice instead of forcing
  `devgeta` — see ADR-0061 §3.
