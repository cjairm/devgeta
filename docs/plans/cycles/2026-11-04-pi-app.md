# Cycle: Pi as a third AI-coder app

**Date:** 2026-11-04
**Status:** Done

## Scope

Add Pi (`@earendil-works/pi-coding-agent`, the terminal AI-coding harness) as a
devgeta-managed app. Initial scope is deliberately minimal:

- Install via Pi's official installer script (`https://pi.dev/install.sh`),
  run under `sh` (its shebang is `#!/bin/sh` — the inverse of opencode's,
  see ADR-0059).
- Idempotent detection keyed on the managed-install marker and `pi` on PATH.
- Uninstall removes **only the managed install root** (`~/.pi/agent/install`,
  ADR-0059) — `~/.pi/agent` is Pi's own config/session home and must survive.
- Register the app in `global_config.yaml`'s installed list. No shell feature,
  no alias, no themes, no shared skills, no `coder_launch` wiring, and
  **no entry in the agent-sync contract** — parity with claude/opencode is
  explicitly out of scope and will be decided later.

## Non-goals

- Themes, Gruvbox palette, shared skills/commands — deferred until the
  maintainer decides how devgeta configures Pi.
- A picker between coders — deferred.
- Updating the two-agent sync test — untouched; it covers claude/opencode only.

## Accepted review outcomes

- **Install-phase ordering**: terminal apps run before the language phase, so a
  clean-machine full install can reach Pi before Node exists. Pi's script fails
  with instructions; re-run after `dg install --only languages`. Reordering the
  category phases is deferred.
- **Install-channel verification** (rejected, ADR-0059): the official-script
  channel mirrors ADR-0047's accepted opencode decision.
